# Codec Fuzzing Harnesses (G36)

> Built 2026-08-08 on branch `open5gs`, third item off the
> [138](138-open5gs-gap-survey.md) first wave and its **cheapest** new item.
> open5gs ships **8 libFuzzer harnesses with seed corpora** (NAS-EPS, NAS-5GS,
> NGAP, S1AP, PFCP, GTP, SBI ×2) and its HEAD commit at survey time was literally
> a PFCP F-TEID bounds fix — "this is where interop bugs live" (138 §3, G36). Rust
> closes the memory-safety *class* (no out-of-bounds reads become RCE), but a
> parser can still **panic** on malformed input — an index, a slice range, an
> `unwrap`, an arithmetic overflow — and every radian codec is fed unauthenticated
> bytes straight off the wire (NGAP/NAS over SCTP, PFCP/GTP-U over UDP, RRC/F1AP
> inside them). A panic in an NF's decode path is a remote DoS. This adds
> `cargo-fuzz` targets over all six codec crates, seeded from radian's own golden
> messages plus open5gs's corpora.

## What was built

A new **`fuzz/`** crate (a detached cargo-fuzz workspace, excluded from the root
workspace by convention so its nightly/sanitizer build never touches
`cargo test --workspace`).

### `fuzz/src/lib.rs` — the fuzz bodies

One `run_*(&[u8])` per wire surface, each driving the **exact** entry point an NF
feeds network bytes into, and re-encoding whatever decodes (so "decoded but
panics on re-encode" is caught too):

| Target | Entry point(s) | Fed by |
|---|---|---|
| `ngap` | `NGAP_PDU::decode` → `.encode()` | AMF N2 (`main.rs:1647`) |
| `nas` | `decode_nas_5gs_message` → `gmm_message_type` + `encode`; `parse_{authentication_request,nssai_value,rejected_nssai_value}`, `accept_5gsm_cause` | AMF/SMF N1 |
| `pfcp` | `handle_n4` against a fresh `UpfState` | UPF N4 (whole ingest) |
| `gtpu` | `parse`, `parse_nr_ran_container`, `decap` | UPF/gNB N3/N9/F1-U |
| `rrc` | `parse_{ul,dl}_{ccch,dcch}` | gNB/DU SRB0/1 |
| `f1ap` | `decode` | CU↔DU |

The contract: these bodies must **never panic on any input**. A panic is a
finding — libFuzzer writes the crashing input to `fuzz/artifacts/` for a
regression seed.

### `fuzz/fuzz_targets/*.rs` — six libFuzzer binaries

Each is a three-line `fuzz_target!` shim over the matching `run_*`. Run with
`cargo +nightly fuzz run <target>` (needs a nightly toolchain + the sanitizer
runtime; both already present).

### `fuzz/corpus/<target>/` — seed corpora

- **Radian-built golden messages** — every builder the NFs actually emit,
  generated by `cargo run --bin make_corpus` (stable): 10 NGAP procedures, the
  5GMM auth messages, the four N4 messages, all nine GTP-U frame shapes, the
  SRB0/1 RRC messages, the CU↔DU F1AP procedures. Mutating from valid framing
  finds bugs orders of magnitude faster than discovering the header from zero.
- **open5gs-lifted seeds** (`o5gs-*.bin`) — the NAS-5GS, PFCP and GTP corpora
  from `~/open5gs/tests/fuzzing/*_seed_corpus.zip`, the three protocols radian
  speaks on the same wire. (open5gs's NGAP/S1AP/SBI harnesses have no committed
  corpus, and S1AP/NAS-EPS are 4G — not radian surfaces.)

### `fuzz/src/lib.rs` — stable-toolchain regression net

`corpus_replays_clean` replays **every committed seed** through its fuzz body on
the **stable** toolchain (no nightly, no sanitizer) — so any input that ever
crashed a codec stays fatal in CI forever, and the corpus is exercised by the
normal test run even though the fuzzers themselves need nightly.

## Boundaries / notes

- **`fuzz/` is out of the root workspace.** `cargo test --workspace` never builds
  it; `cd fuzz && cargo test` runs the replay net; `cargo +nightly fuzz run`
  runs a real campaign. This keeps the sanitizer/nightly requirement off every
  normal build.
- **What's covered is the decode path, not the NF state machine.** `run_pfcp`
  drives `handle_n4` (parse + IE walk + a session insert), which is the parsing
  surface; it does not fuzz multi-message sequences. Sequence/transaction fuzzing
  is a later, stateful harness.
- The bodies swallow `Err`/`None` and only fail on a panic — a rejected malformed
  message is *correct* behaviour, the whole point being that rejection must not
  be a crash.
- Corpus minimization (`cargo fuzz cmin`) and CI wiring (a timed campaign per
  target) are left for the ops pass (G42) — this lands the harnesses + seeds +
  the stable regression net.

## Verification

- `cd fuzz && cargo run --bin make_corpus` — regenerates all radian-built seeds
  clean (47 committed seeds across the six targets: 10 ngap, 6 nas, 7 pfcp,
  10 gtpu, 9 rrc, 5 f1ap — the last two families all radian-built, the rest
  radian-built plus the `o5gs-*` open5gs seeds).
- `cd fuzz && cargo test` — `corpus_replays_clean` green: every committed seed
  (radian-built + open5gs-lifted) replays through its codec with no panic.
- Short smoke campaigns (`cargo +nightly fuzz run <t> -- -runs=20000`) per
  target, all built under the sanitizer and **finished with zero crashes**:

  | Target | edge cov | features | corpus | notes |
  |---|---|---|---|---|
  | ngap  | 10073 | 14875 | 815 | deepest surface (APER) |
  | rrc   | 10947 | 13482 | 996 | APER |
  | f1ap  |  9076 | 11133 | 856 | APER |
  | nas   |  2569 |  3269 | 543 | hand TLV |
  | pfcp  |  2430 |  3875 | 373 | rs-pfcp TLV |
  | gtpu  |   110 |   159 |  39 | tiny header codec |

  (Campaign-grown corpora are `.gitignore`d — only the curated seeds are
  tracked; a longer campaign is the ops follow-up.)
- Root `cargo test --workspace --exclude bdd` unaffected (fuzz crate is detached).

## Known limitations / next steps

- Stateful/sequence fuzzing (multi-message N4 or N2 exchanges).
- CI: a bounded per-target campaign + corpus artifact upload (fold into G42).
- `cargo fuzz cmin` corpus minimization once campaigns have grown the corpora.
- The other radian codecs with no dedicated target yet (`pdcp`, `sdap`) are thin
  and mostly length-prefixed; add them if a real decode surface appears.
